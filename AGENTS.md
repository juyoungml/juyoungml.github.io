# AGENTS.md

Project guide for AI coding assistants (Codex, Cursor, Cline, Claude Code, etc.). Tool-agnostic counterpart to `CLAUDE.md` — read either one; both describe the same codebase. Claude Code reads `CLAUDE.md` by default; tools that read `AGENTS.md` get this file.

## Project

Personal site at [juyoung.site](https://juyoung.site). Next.js 14 (Pages Router), TypeScript strict, TailwindCSS, static export to GitHub Pages. Bilingual EN / KO.

## Setup

```bash
npm install
npm run dev
```

## Verification before claiming done

```bash
npm run format:check
npm run lint
npm run typecheck
npm run build
```

CI runs all four on every push and PR. Don't skip any.

## Where to put things

- **A new page** → `pages/<route>.tsx` (or `pages/ko/<route>.tsx` for the Korean variant). Use `getStaticProps`/`getStaticPaths` only — there is no SSR or API at request time.
- **A new blog post** → `content/blog/<slug>.mdx` with frontmatter (`title`, `date`, `description`, `tags`). Optional Korean version at `content/blog/ko/<slug>.mdx`. No code changes needed; sitemap, RSS, OG image, Pagefind index are generated by postbuild scripts.
- **A new paper** → `content/papers/<slug>.mdx` with paper frontmatter (authors, venue, year, links, BibTeX).
- **Shared site copy in two languages** → `lib/i18n.ts` STRINGS map. Both EN and KO entries required.
- **A new component** → `components/<Name>.tsx`. Blog-specific UI goes under `components/blog/`. Paper-specific under `components/papers/`.
- **A new build step** → `scripts/<name>.mjs` (plain JS, no transpiler), append to the `postbuild` chain in `package.json`.

## Conventions

- **No comments unless the WHY is non-obvious.** Don't explain WHAT code does — names already do that. Don't write "added for X" or reference current callers — those rot. Workarounds with a citation to the underlying bug are fine.
- **Single source of truth for site constants**: `lib/site.ts` (`SITE_URL`, `SITE_AUTHOR`, etc.). Don't hardcode the domain.
- **i18n**: KO bio prose lives in `lib/i18n.ts`. Korean uses 합니다체 (formal). Brand names stay English (GitHub, LinkedIn, Google Scholar, Semantic Scholar) — no hangul transliterations.
- **No emojis** in source or user-facing copy. Existing codebase has zero; keep it.
- **TypeScript strict.** No `any`. If you genuinely need a loose type, use `unknown` or a narrowly-scoped helper type.
- **Static export-safe code.** No `getServerSideProps`, no API routes, no `next/image` with optimization (`images.unoptimized: true`).
- **Korean glyphs**: components that render Korean must be reachable via `lang="ko"` on a wrapping element so Pretendard kicks in.

## Static-export gotchas

- `process.env.NEXT_PUBLIC_*` is read at build time and baked into the bundle. Required env vars must be set in the GitHub Actions build step.
- Optional features (Buttondown newsletter, search-console meta, view counts) degrade silently when their env vars are unset — same pattern; follow it for new optional integrations.
- Client-side code can't import server-only modules (`fs`, `path`). If logic needs both, split into a build-time script under `scripts/` writing a JSON file the client fetches.

## Analytics, comments, newsletter (third-party services)

- Umami (self-hosted) — script and website ID are public, hardcoded in `pages/_document.tsx`. Gated to `NODE_ENV === 'production'`. Custom events via `lib/analytics.ts::track()`.
- Giscus — hardcoded repo / category in `components/blog/Comments.tsx`. Discussions must be enabled on the repo; Giscus GitHub App must be installed.
- Buttondown, search consoles, view counts — env-driven; see `README.md` for the exact secret names.

## Deployment

`main` push → CI workflow → deploy workflow → push `out/` to `gh-pages` → GitHub Pages serves from `gh-pages` branch root at `juyoung.site` (custom domain in `public/CNAME`).

## Do / Don't

**Do:**

- Read the relevant existing file before editing it. The codebase has consistent patterns.
- Run the four verification commands locally before pushing.
- For visual changes, screenshot the result before reporting done.

**Don't:**

- Add abstractions for hypothetical future variants. Three similar lines is fine.
- Add backwards-compat shims for code that has no live callers — delete it.
- Force-push `main`.
- Write planning/decision/analysis docs unless asked.
- Skip CI checks (`--no-verify` on commits, `[skip ci]` on commit messages) without an explicit reason.
